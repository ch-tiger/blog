NPU（Ascend）适配全面分析

SGLang 的 NPU 适配是一个 分层替换 + 插件注册 的架构模式，没有对原有 GPU 代码进行大规模修改，而是通过 策略模式 + 装饰器注册 + 条件导入 在关键路径上插入 NPU 专属实现。下面从 5 个层次详细拆解。

一、设备发现与后端初始化（Entry Point）

文件： utils/common.py:149-158

def is_npu() -> bool:
    if not hasattr(torch, "npu"):
        return False
    if not torch.npu.is_available():
        raise RuntimeError("torch_npu detected, but NPU device is not available.")
    return True
  • is_npu() 是全局设备检测函数，通过检测 torch.npu 属性和 torch.npu.is_available() 来判断
  • 在模块加载时以 _is_npu = is_npu() 形式缓存结果，遍布 30+ 个文件

初始化链：

  1. server_args.py:1112-1116 — _handle_npu_backends() 调用 set_default_server_args(self)，强制设置 attention_backend="ascend"、禁用 CustomAllReduce、根据 NPU 型号设置 page_size/chunked_prefill_size/cuda_graph_max_bs 等默认参数
  2. model_runner.py:206-209 — 在模块加载时调用 init_npu_backend()，该函数只执行一次：
    • 导入 sgl_kernel_npu（NPU 自定义算子库）
    • 导入 torch_npu 及 transfer_to_npu（将 torch.cuda 接口重映射到 torch.npu）
    • 关键技巧：torch.cuda.is_available = lambda: False — 因为 transfer_to_npu 会把 torch.cuda.is_available mock 成 True，但 sglang 很多路径靠这个判断是 CUDA 还是非 CUDA，所以强制恢复

二、注意力机制适配（最核心部分）

NPU 适配最复杂的是注意力层，分为 AttentionBackend（运行时调度）和 DeepSeek MLA forward 方法（模型前向）两个层面。

2.1 AttentionBackend 注册机制

文件： layers/attention/attention_registry.py:79-85

@register_attention_backend("ascend")
def create_ascend_backend(runner):
    from sglang.srt.hardware_backend.npu.attention.ascend_backend import AscendAttnBackend
    return AscendAttnBackend(runner)

通过装饰器注册 "ascend" 字符串到 AscendAttnBackend 类的映射。当 server_args 中 attention_backend="ascend" 时，框架自动使用这个后端。

2.2 AscendAttnBackend 结构（~2100 行）

文件： npu/attention/ascend_backend.py

继承自 AttentionBackend（抽象基类），实现了以下核心方法：

方法对应场景NPU 特有算子
forward_extend()Prefill 阶段torch_npu._npu_flash_attention_qlens / torch.ops.npu.npu_fused_infer_attention_score / torch_npu.atb.npu_ring_mla
forward_decode()Decode 阶段torch_npu._npu_paged_attention / torch.ops.npu.npu_fused_infer_attention_score / torch_npu._npu_paged_attention_mla
forward_decode_graph()CUDA Graph 模式 decodetorch_npu.npu_fused_infer_attention_score.out（带 workspace 预分配）
forward_mtp()投机解码 MTP同上
forward_mixed()Mixed Chunk 模式torch.ops.npu.npu_fused_infer_attention_score
forward_sparse()NSA 稀疏注意力torch_npu.npu_sparse_flash_attention

适配模式： Ascend 提供了三种注意力算子路径，按优先级和环境变量选择：

  1. FIA（ASCEND_USE_FIA=1）→ 使用 npu_fused_infer_attention_score，功能最全（支持 MLA/RoPE/PA）
  2. 传统路径 → 使用 _npu_flash_attention_qlens（extend）和 _npu_paged_attention（decode）
  3. SDPA Fallback → AscendTorchNativeAttnBackend（当 FIA 不支持时，如 cross attention、精度问题）

2.3 AttnForwardMethod 调度（DeepSeek MLA 模型特有）

对于 DeepSeek V2/V3 这类使用 MLA 的模型，不是通过 AttentionBackend 调用，而是在模型的 dispatch_attn_forward_method() 中决定。

文件： deepseek_common/attention_backend_handler.py:38-53

def handle_attention_ascend(attn, forward_batch):
    # extend 阶段 → MHA_NPU（或 DSA_NPU 如果有 indexer）
    # decode 阶段 → MLA_NPU（或 DSA_NPU）
    if forward_batch.forward_mode.is_extend():
        return AttnForwardMethod.MHA_NPU  # 或 DSA_NPU
    else:
        return AttnForwardMethod.MLA_NPU  # 或 DSA_NPU

这里的 MHA_NPU / MLA_NPU / DSA_NPU 三个枚举值映射到 npu/modules/deepseek_v2_attention_mla_npu.py 中的 forward_mha_prepare_npu/forward_mha_core_npu 等函数。这些函数在 deepseek_v2.py:174-182 被条件导入：

elif _is_npu:
    from sglang.srt.hardware_backend.npu.modules.deepseek_v2_attention_mla_npu import (
        forward_dsa_core_npu, forward_dsa_prepare_npu,
        forward_mha_core_npu, forward_mha_prepare_npu,
        forward_mla_core_npu, forward_mla_prepare_npu,
    )

三、KV Cache 与内存管理

3.1 Token-to-KV Pool

文件： npu/memory_pool_npu.py

  • NPUMHATokenToKVPool（继承 MHATokenToKVPool）：
    • 连续内存分配：[2, layer_num, num_pages+1, page_size, head_num, head_dim]，+1 的 slot 0 用于 dummy padding
    • FIA 模式下 KV buffer 变为 list of per-layer tensors，方便 scatter_nd_update
    • set_kv_buffer() 使用 torch_npu.npu_scatter_nd_update_() 或 torch_npu._npu_reshape_and_cache()（FIA vs 传统）
  • NPUMLATokenToKVPool（继承 MLATokenToKVPool 的父类）：
    • K_buffer 存 kv_lora_rank，V_buffer 存 qk_rope_head_dim，完全分离
    • 均使用 npu_scatter_nd_update_ 写入

3.2 Paged 内存分配器

文件： npu/allocator_npu.py

NPUPagedTokenToKVPoolAllocator 继承 PagedTokenToKVPoolAllocator：

  • alloc_extend() — 小 batch（<200 pages）使用 sgl_kernel_npu.mem_cache.allocator.alloc_extend_kernel（NPU 专属 kernel），大 batch 走原始的 alloc_extend_naive
  • alloc_decode() — 与 CUDA 版本逻辑相同但适配了 NPU 的数据类型

3.3 集成点

在 model_runner_kv_cache_mixin.py:285-344 中：

if self.server_args.attention_backend == "ascend" and not self.mambaish_config:
    if self.is_hybrid_swa:
        token_to_kv_pool_class = NPUMHATokenToKVPool
    elif self.use_mla_backend:
        token_to_kv_pool_class = NPUMLATokenToKVPool
    else:
        token_to_kv_pool_class = NPUMHATokenToKVPool

四、分布式通信

4.1 NpuCommunicator

文件： npu_communicator.py

一个简单的封装，使用 PyTorch 原生 dist.all_reduce 和 dist.all_gather_into_tensor。与 CUDA 的 CustomAllReduce（NVLink 优化）不同，NPU 通信强制使用标准 NCCL/RCCL 的 PyTorch wrapper，没有自定义 reduce 融合。

  • 在 server_args 中强制 disable_custom_all_reduce = True
  • 在 parallel_state.py:426-428 中根据 use_npu_communicator 标志初始化

4.2 分层 Cache 通信

server_args.py:83-88：

if args.enable_hierarchical_cache:
    args.hicache_io_backend = "kernel_ascend"  # NPU 专属后端

五、MoE 与量化适配

5.1 MoE Gating

文件： npu/moe/topk.py

fused_topk_npu() — 替换原生的 TopK 选择：

  • 无 grouped routing + 无 correction_bias → 使用 torch.ops.npu.npu_moe_gating_top_k_softmax
  • 有 grouped routing + correction_bias → 使用 torch.ops.npu.npu_moe_gating_top_k
  • 其他情况 → fallback 到 select_experts()（torch native）

5.2 Fused MoE

文件： npu/quantization/fused_moe_method_npu.py

提供了多种量化 MoE 方法：

  • npu_fused_experts() — AWQ/GPTQ 量化 MoE 的 NPU 路径
  • NPUW8A8Int8DynamicMoEMethod / NPUW4A8Int8DynamicMoEMethod / NPUW4A4Int4DynamicMoEMethod
  • fused_moe_npu() — 被 dbrx.py 和 xverse_moe.py 直接使用

5.3 量化 Linear 方法

文件： npu/quantization/linear_method_npu.py

  • NPUW8A8Int8LinearMethod — W8A8 静态量化：npu_quant_matmul + npu_quantize
  • NPUW8A8Int8DynamicLinearMethod — W8A8 动态量化
  • NPU_W4A4DynamicLinearMethod — W4A4 动态量化
  • 这些方法被 compressed_tensors 和 modelslim 量化方案在 _is_npu 时使用

六、CUDA Graph 替代方案

文件： npu/graph_runner/npu_graph_runner.py

NPU 有自己的 Graph 实现（torch.npu.NPUGraph），在 patch_model_npu() 上下文中封装。支持：

  • torch.npu.NPUGraph 的 capture/replay
  • sgl_kernel_npu.graph_runner.ops 中的 NPU 专属 graph 算子
  • 在 compilation/npu_piecewise_backend.py 中，NPU 版本的 NPUPiecewiseBackend（继承 CUDAPiecewiseBackend）将 torch.cuda.CUDAGraph 替换为 torch.npu.NPUGraph

八、适配模式总结

┌────────────────────────────────────────────────────────────────┐
│                    SGLang 框架核心层                             │
│   server_args → model_runner → ForwardBatch → AttentionBackend  │
└────────────────────┬───────────────────────────────────────────┘
                     │ is_npu() 检查
     ┌───────────────┴───────────────┐
     ▼                               ▼
  非 NPU 路径                    NPU 路径（此目录分析）
  ──────────               ────────────────────────
  原始代码流                条件导入 + 注册替换
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        AttentionBackend  KV Cache/Memory   MoE/Quant
        ───────────────  ────────────────  ──────────
        "ascend" 注册     NPUMHATokenToKVPool fused_topk_npu
        AscendAttnBackend NPUMLATokenToKVPool NPUW8A8Int8*
        handle_attention  NPUPagedAllocator   npu_fused_experts
        _ascend
              │
              ▼
        Ascend 原生算子
        torch.ops.npu.* / torch_npu.* / sgl_kernel_npu.*

核心策略：

  1. 设备感知 — is_npu() 作为全局开关，在模块加载时缓存
  2. 条件导入 — if _is_npu: from ..._npu import ... 替换关键函数
  3. 继承覆盖 — NPU 类继承 GPU 基类，只重写需要差异的方法（如 NPUMHATokenToKVPool）
  4. 装饰器注册 — @register_attention_backend("ascend") 将 NPU 后端插入框架的 AttentionBackend 工厂
  5. 策略注册 — AttentionBackendRegistry.register("ascend", handle_attention_ascend) 调度 DeepSeek 的 MLA 前向策略
  6. 透明算子 — 通过 sgl_kernel_npu（自定义 NPU 算子库）暴露与 sgl_kernel 相同接口的算子，模型层基本无感知
