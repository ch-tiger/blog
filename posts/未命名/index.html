可行，而且是一个很好的“零侵入”方案，但功能不完全一样。更准确地说：

TensorBoard event exporter 能把“已经写入 TensorBoard 的指标”暴露给 Prometheus；直接在训练进程里加 Prometheus metrics 能暴露“训练运行时现场所有你想拿的指标”。

可行性 Megatron-LM 已经在 training_log() 里大量写 TensorBoard scalar，入口在 training.py：

if writer and (iteration % args.tensorboard_log_interval == 0):
    writer.add_scalar('learning-rate', learning_rate, iteration)
    writer.add_scalar('batch-size', batch_size, iteration)
    writer.add_scalar(key, loss_dict[key], iteration)
    writer.add_scalar('loss-scale', loss_scale, iteration)
    writer.add_scalar('grad-norm', grad_norm, iteration)
    ...

所以你完全可以写一个独立 exporter：

  1. 训练进程正常启用 TensorBoard：
    --tensorboard-dir /path/to/tensorboard_logs
--tensorboard-log-interval 1
--log-timers-to-tensorboard
--log-throughput
  2. exporter 进程读取 /path/to/tensorboard_logs/events.out.tfevents.*
  3. exporter 自己监听 :8080/metrics
  4. Prometheus scrape exporter
  5. Grafana 查 Prometheus

这个方案不需要改 Megatron-LM 源码，部署上也更舒服。

不完全等价的地方 不等价主要有 4 点：

  1. 指标覆盖范围受 TensorBoard 写入限制
    TensorBoard 没写的指标，exporter 就拿不到。比如 throughput 只有在 --log-throughput 且 --log-timers-to-tensorboard 时才会写入 TensorBoard，位置在 training.py。内存指标也要开 --log-memory-to-tensorboard。

  2. 有延迟
    TensorBoard SummaryWriter 有队列，默认 tensorboard_queue_size = 1000，见 training_config.py。event 文件落盘、exporter 读取、Prometheus scrape 都会带来延迟。训练内直接暴露 metrics 延迟更低。

  3. 指标语义会更像“日志回放”
    Prometheus 更偏当前状态和时间序列采样。TensorBoard event 是 append-only 日志，exporter 通常要维护“每个 tag 的最新 step/value”。可以展示曲线，但要小心 event 文件 rotation、断点续训、重复 step、多个 event 文件的问题。

  4. 多 job / 多 rank 标签要自己处理
    Megatron 的 TensorBoard writer 只在 rank == world_size - 1 创建，见 global_vars.py，这点反而是好事，不会多 rank 重复写。但 exporter 需要给指标补上 run/job/host/logdir 这类 label，否则 Grafana 上多个训练任务会混在一起。

推荐实现方式 我建议做独立 exporter，而且用它作为第一版。它满足“不侵入源码”，风险低，Prometheus/Grafana 链路能很快跑通。

技术选择：

pip install prometheus-client tensorboard

核心读取可以用 TensorBoard 的：

from tensorboard.backend.event_processing.event_accumulator import EventAccumulator

exporter 逻辑：

acc = EventAccumulator(logdir)
acc.Reload()

for tag in acc.Tags()["scalars"]:
    events = acc.Scalars(tag)
    latest = events[-1]
    gauge.labels(tag=sanitize(tag)).set(latest.value)

Prometheus metric 可以设计成一个通用指标：

megatron_tensorboard_scalar{tag="learning_rate", run="gpt_7b"} 0.00012
megatron_tensorboard_scalar_step{tag="learning_rate", run="gpt_7b"} 1200
megatron_tensorboard_scalar_wall_time{tag="learning_rate", run="gpt_7b"} 1780936712

也可以把常用 tag 映射成更漂亮的独立指标：

megatron_train_learning_rate
megatron_train_loss
megatron_train_throughput_tflops_per_gpu

第一版我会选“通用 scalar + tag label”，省事、覆盖全、对 Megatron tag 变化更稳。

Grafana 查询示例

megatron_tensorboard_scalar{tag="lm_loss"}
megatron_tensorboard_scalar{tag="learning-rate"}
megatron_tensorboard_scalar{tag="throughput"}
megatron_tensorboard_scalar{tag="iteration-time"}
megatron_tensorboard_scalar{tag="grad-norm"}
megatron_tensorboard_scalar{tag="mem-allocated-bytes"}

结论 可行，适合作为非侵入式方案；功能接近，但不完全一样。只要你接受“只能暴露 TensorBoard 已写入的指标”和“有几秒到几十秒延迟”，这个方案非常实际。要做到和训练内置 Prometheus 完全一致，则需要确保所有关心的指标都写入 TensorBoard，并处理好 event 文件 reload、重复 step、多个 run 的 label。
