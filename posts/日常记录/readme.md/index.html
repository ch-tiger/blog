最合理的组合做法（业界实践）：

第 1 步：方案 A 冒烟
  → 100 条 prompt，token 匹配率 > 0.85 → 继续往下
  → 否则直接 C 定位

第 2 步：方案 B 验收
  → MMLU / GSM8K / HumanEval 各跑一遍
  → acc 差 < 1% → 精度等价，可上线
  → acc 差 > 2% → 回到第 3 步

第 3 步：方案 C 定位（仅当 B 不达标）
  → 逐算子对比，找到第一个超阈值的算子
  → 针对该算子修复（换实现 / 调精度模式）

对你的场景（H20 vs NPU，SGLang），最合理的方案：

主用 lm_eval 做精度验收，msprobe 做根因定位，自定义输出比对只做冒烟。

具体优先级：

  1. 先用方案 A 100 条 prompt 快速冒烟（半小时）
  2. 通过后用方案 B lm_eval 跑 MMLU+GSM8K+HumanEval 验收（几小时）
  3. B 不达标时，用方案 C msprobe 逐算子定位（按需）
# H20 侧
lm_eval --model sglang \
    --model_args base_url=http://h20-host:30000,model=meta-llama/Meta-Llama-3-8B-Instruct \
    --tasks gsm8k,mmlu,humaneval \
    --num_fewshot 0 \
    --batch_size 8 \
    --output_path results_h20/

# NPU 侧（同样命令，只换 base_url）
lm_eval --model sglang \
    --model_args base_url=http://npu-host:30000,model=meta-llama/Meta-Llama-3-8B-Instruct \
    --tasks gsm8k,mmlu,humaneval \
    --num_fewshot 0 \
    --batch_size 8 \
    --output_path results_npu/

对比：

import json
h20 = json.load(open("results_h20/.../results.json"))
npu = json.load(open("results_npu/.../results.json"))
for task in ["gsm8k","mmlu","humaneval"]:
    a, b = h20["results"][task]["acc"], npu["results"][task]["acc"]
    print(f"{task}: H20={a:.4f}  NPU={b:.4f}  diff={b-a:+.4f}")

关键约束：

  • temperature=0、--seed 42
  • --num_fewshot 两边必须一致
  • lm_eval 的 sglang 模型类已内置，直接用 --model sglang
  • 同一份 --tasks，别加随机子集

msprobe 本身设计目标是"NPU 对标其他框架"（如 PyTorch / MindSpore），典型用法：

pip install msprobe
# 1. H20 侧 dump 基准 tensor
from msprobe.pytorch import PrecisionDebugger
# 在 H20 的 forward 里 hook 关键算子，dump 输入输出

# 2. NPU 侧 dump 对应 tensor
from msprobe.mindspore import PrecisionDebugger  # 或 ascend 后端
# 同样 hook 同名算子

# 3. 比对
msprobe --compare h20_dump/ npu_dump/ \
    --output_path compare_result/

它生成的报告类似：

Layer                  max_diff    rmse    cosine    status
layers.0.self_attn     0.012       0.003   0.9998    PASS
layers.0.mlp           0.234       0.089   0.9871    FAIL  ← 这里发散
layers.1.self_attn     0.045       0.012   0.9989    PASS
...

难点：

  • H20 侧走 PyTorch / SGLang，NPU 侧走 torch_npu 或 MindSpore，算子命名要对齐（SGLang 的 LlamaAttention 在 MindSpore 里可能叫别的）
  • 需要在两边的 forward 里插入相同位置的 hook
  • msprobe 主推 MindSpore ↔ PyTorch 比对，SGLang（PyTorch 生态）对比 NPU 时，本质是 PyTorch CUDA vs torch_npu，可以用它的 PyTorch 模式 dump H20，再用 ascend 模式 dump NPU
