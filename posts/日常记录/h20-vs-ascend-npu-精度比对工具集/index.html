针对 Qwen3.5-Flash（step3.5-flash） 模型、NPU 后端为 SGLang Ascend，

完成"冒烟 → 验收 → 定位"三步联动的跨硬件精度比对。

本目录为独立工具集，不依赖也不修改 SGLang 主仓代码（除通过官方插件机制 SGLANG_PLUGINS 在服务进程内挂载 hook）。

一、文件清单与作用

| 文件 | 所属步骤 | 作用 |

|—|—|—|

| README.md | — | 本文档 |

| prompts.jsonl | A | 20 条统一输入（数学/代码/翻译/常识），两端共用 |

| gen_outputs.py | A | 向 SGLang 服务发请求生成确定性输出；兼容 /generate 与 OpenAI /v1/completions；含健康等待、本地 tokenizer 兜底编码 token id |

| compare_outputs.py | A | 比对两份输出：token 匹配率、文本相似度、长度比；按 H20-vs-NPU 阈值给 PASS/FAIL 判定 |

| run_smoke.sh | A | 一键冒烟：按 SGLang Ascend 标准参数启动服务 → 生成输出 → 自动关闭 |

| run_lmeval.sh | B | lm_eval 验收：跑 gsm8k + mmlu + humaneval |

| lmeval_diff.py | B | 汇总两端 lm_eval results.json，按任务给 acc 差值与 PASS/FAIL |

| msprobe_dump_plugin/pyproject.toml | C | 插件打包配置，注册 entry_points: sglang.srt.plugins |

| msprobe_dump_plugin/sglang_msprobe_dump/init.py | C | 在线 dump 插件：用官方 HookRegistry 包 ModelRunner.__init__，模型加载后挂 forward hook 到每个 Step3p5DecoderLayer 子模块，dump input/output tensor 到 CPU fp32 |

| run_msprobe_compare.sh | C | 比对入口：优先 msprobe compare，不可用回退到 _torch_compare.py |

| _torch_compare.py | C | 纯 torch 回退比对：每 tensor 的 max/mean diff + cosine，按发散排序，标首个发散点 |

| run_all.sh | 全部 | 总入口：依次跑 A → B → C，每步留下独立 artifact |

关键设计点

  1. Step C 在线 dump，不另起离线 Engine（本轮重构的核心）。

   旧方案用 Engine(**kwargs) 重建推理，dump 链路与真实服务可能不一致。

   新方案走 SGLang 官方插件机制（python/sglang/srt/plugins/init.py），

   load_plugins() 在 scheduler 子进程启动时执行（scheduler.py:4181），

   插件用 HookType.AROUND 包 ModelRunner.__init__，原 __init__ 返回后

   self.model 已装配（model_runner.py:693），

   此时挂 forward hook，dump 的就是 Step A/B 用的同一条服务链路。

  1. NPU 启动参数对齐官方测试（python/sglang/test/ascend/gsm8k_ascend_mixin.py）：

   --attention-backend ascend --disable-cuda-graph --mem-fraction-static 0.8，

   环境变量 PYTORCH_NPU_ALLOC_CONF=expandable_segments:True、

   ASCEND_LAUNCH_BLOCKING=1（同步执行，保证可复现）。

  1. 全程确定性：temperature=0、--seed 42、两端 dtype=bfloat16。

  2. 判定阈值（H20 vs NPU 经验值，内置到各比对脚本）：

   - Step A：token 匹配率 > 0.85、文本相似度 > 0.92、长度比 0.9~1.1

   - Step B：各任务 |acc 差| < 1%

   - Step C：max_abs_diff > 0.01 的 tensor 标记为 DIVERGED

二、使用方法

前置：在 H20 和 NPU 两台机各装一次 Step C 插件


cd .sisyphus/precision_compare/msprobe_dump_plugin
pip install -e .

# 验证 entry_points 已注册
python -c "from importlib.metadata import entry_points; \
  print([e.name for e in entry_points(group='sglang.srt.plugins')])"
# 应输出包含 'msprobe_dump'

方式一：一键全流程（推荐）

在 H20 机和 NPU 机分别执行：


# H20 机
bash run_all.sh h20 /data/models/Qwen/Qwen3.5-Flash

# NPU 机（先 source 昇腾环境）

source /usr/local/Ascend/ascend-toolkit/set_env.sh
bash run_all.sh npu /data/models/Qwen/Qwen3.5-Flash

run_all.sh 依次执行：

  • Step A：run_smoke.sh 启停服务，产出 outputs_<side>.jsonl

  • Step B：长驻服务跑 lm_eval，产出 results_<side>/

  • Step C：带插件重启服务触发 dump，产出 dump_<side>/

脚本结束会提示把三类 artifact 拷到同一台机汇总。

方式二：分步执行（调试用）

Step A：冒烟（约 30 分钟）


# H20 机

bash run_smoke.sh h20 /data/models/Qwen/Qwen3.5-Flash cuda

# NPU 机

source /usr/local/Ascend/ascend-toolkit/set_env.sh
bash run_smoke.sh npu /data/models/Qwen/Qwen3.5-Flash npu

把 outputs_npu.jsonl 拷到 H20 机，比对：


python compare_outputs.py \
    --baseline outputs_h20.jsonl \
    --target   outputs_npu.jsonl

输出 token 匹配率、文本相似度、长度比，并给 PASS/FAIL 判定。

PASS → 进 Step B；FAIL → 直接进 Step C 定位。

Step B：验收（数小时）

两端各启动一个常驻服务（用 run_smoke.sh 里的参数，但手动启停）：


# H20

python -m sglang.launch_server --model-path /data/models/Qwen/Qwen3.5-Flash \
    --port 30000 --dtype bfloat16 --trust-remote-code --seed 42 \
    --device cuda --mem-fraction-static 0.85 &

# NPU

source /usr/local/Ascend/ascend-toolkit/set_env.sh

python -m sglang.launch_server --model-path /data/models/Qwen/Qwen3.5-Flash \
    --port 30000 --dtype bfloat16 --trust-remote-code --seed 42 \
    --device npu --attention-backend ascend --disable-cuda-graph \
    --mem-fraction-static 0.8 &

分别跑 lm_eval：

bash run_lmeval.sh h20 http://localhost:30000
bash run_lmeval.sh npu  http://localhost:30000

汇总比对：

python lmeval_diff.py results_h20 results_npu

输出每个任务的 H20/NPU acc、差值、PASS/FAIL。

全部 PASS → 精度等价，可上线；任一 FAIL → 进 Step C。

Step C：根因定位（按需）

两端各带插件启动服务并触发一次 forward：


# H20

SGLANG_PLUGINS=msprobe_dump MSDUMP_DIR=./dump_h20 MSDUMP_SIDE=h20 \
    python -m sglang.launch_server --model-path /data/models/Qwen/Qwen3.5-Flash \
    --dtype bfloat16 --trust-remote-code --seed 42 --device cuda &

python gen_outputs.py --base-url http://localhost:30000 \
    --prompts prompts.jsonl --output /tmp/t.jsonl --max-new-tokens 16

# 关闭服务

# NPU
source /usr/local/Ascend/ascend-toolkit/set_env.sh
SGLANG_PLUGINS=msprobe_dump MSDUMP_DIR=./dump_npu MSDUMP_SIDE=npu \
    python -m sglang.launch_server --model-path /data/models/Qwen/Qwen3.5-Flash \
    --dtype bfloat16 --trust-remote-code --seed 42 --device npu \
    --attention-backend ascend --disable-cuda-graph --mem-fraction-static 0.8 &
    
python gen_outputs.py --base-url http://localhost:30000 \
    --prompts prompts.jsonl --output /tmp/t.jsonl --max-new-tokens 16

比对：

bash run_msprobe_compare.sh ./dump_h20 ./dump_npu ./msprobe_report

输出每个 decoder 层每个子模块（self_attn / moe / mlp / share_expert /

input_layernorm / post_attention_layernorm）的 max_diff / mean_diff / cosine，

按发散程度排序，并标出首个发散 tensor——这就是精度漂移的起点。

六、常见问题

Q1：Step C 的 dump 目录是空的？

检查：服务启动时是否设了 SGLANG_PLUGINS=msprobe_dump、MSDUMP_DIR、MSDUMP_SIDE；

load_plugins() 只在 scheduler 子进程启动早期执行，主进程设环境变量即可被子进程继承。

验证插件是否被发现：测试 4。

Q2：NPU 侧 lm_eval 报 sglang model 类找不到？

升级 lm-eval 到支持 sglang backend 的版本；或改用 --model local-completions 指向

/v1/completions。

Q3：两端 tokenizer 编码不一致导致 token 对比无意义？

两端对同一句话 AutoTokenizer.encode 结果必须 100% 相同。Qwen3.5-Flash 用官方

HF 权重即可；若用了不同 fast/slow tokenizer 实现，需统一。

Q4：Step C 只想 dump 某几层？

编辑 msprobe_dump_plugin/sglang_msprobe_dump/__init__.py 的 LAYER_SUBMODULES

或在挂 hook 的 for 循环加 if i not in {0, 1, len(layers)-1}: continue。
